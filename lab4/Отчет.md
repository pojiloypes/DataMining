# Лабораторная работа № 4. Вариант 4

## Цель и диагностика

Цель — проверить, почему обычный HTTP-запрос не получает названия товаров, и сравнить три способа сбора: Playwright, прямой запрос JSON и Octoparse.

Источник варианта 4: [ScrapingCourse — JavaScript Rendering](https://www.scrapingcourse.com/javascript-rendering).

| Способ | Названия товаров основного сайта | Названия книг контрольного сайта |
| --- | ---: | ---: |
| requests | 0 | 20 |
| Браузер с JavaScript | 12 | 20 |
| Браузер без JavaScript | 0 | 20 |

Исходный HTML содержит 12 контейнеров товаров, но без названий. Его размер в выводе диагностики — 29 656 символов: `len(html)` считает символы. Название `Bruno Compete Hoodie` отсутствует в исходном HTML, включая скрипты, и появляется в DOM после исполнения JavaScript.

В Network → Fetch/XHR найден `GET https://www.scrapingcourse.com/ajax/products/json`, без параметров. Ответ — JSON со списком товаров; журнал последнего XHR-прогона подтверждает статус 200. Значит, данные можно получать напрямую, без браузера. Контрольный сайт показывает, что requests и парсер работают, когда названия уже находятся в серверном HTML.

## Сбор данных

collect_playwright.py открывает страницу, ждёт появления `.product-name` и одним вызовом `eval_on_selector_all` извлекает название, цену, ссылку и адрес изображения. Цены переводятся в числа, дубликаты убираются по ссылке.

После прокрутки данные собираются повторно. При первом отсутствии новых товаров цикл завершается.

Сбор выполняется в двух режимах: обычном и с блокировкой изображений, шрифтов и медиа. Создаются журнал, таблицы качества и метрик. При ошибке предусмотрено сохранение HTML и скриншота, ресурсы закрываются в `finally`.

| CSS-локатор | Назначение |
| --- | --- |
| `.product-item` | Карточка товара |
| `.product-name` | Название |
| `.product-price` | Цена |


collect_xhr.py получает тот же набор через найденный JSON-адрес. Установлен таймаут 15 секунд. Все 12 товаров приходят одним ответом, поэтому пагинация не используется.

В Octoparse настроена задача с последовательностью **Go to Webpage → Loop Item → Extract Data**. Экспортированы те же четыре поля. Скриншот запуска подтверждает 12 строк за 7 секунд; скриншот workflow показывает структуру.

Оценка устойчивости дана по используемым способам извлечения: XHR не зависит от HTML, но зависит от схемы API.

Блокировка сократила время и трафик. Массовое чтение оказалось быстрее поэлементного в **50,21 раза** в обычном режиме и в **51,14 раза** с блокировкой. Полные результаты находятся в `results/browser/extraction_benchmark.csv`.

После приведения названий столбцов и пробелов к одному виду названия, цены, ссылки и изображения совпали. В каждом наборе 12 уникальных товаров, пропусков нет, цены положительные.

Трафик учитывает тела ответов без заголовков и TLS. Память измеряется в контрольных точках, поэтому это наблюдаемый максимум, а не точный пик. Браузерное время включает запуск, прокрутку, сравнительное чтение и закрытие; XHR-время — запрос, обработку и запись журнала.

## Ограничения и вывод

На выбранном источнике доступны 12 товаров. Поэтому требования о 200 записях, пяти циклах взаимодействия и 20 строках no-code результата не выполнены. Источник не расширялся, товары не дублировались ради объёма.

Для этого сайта удобнее прямой XHR-запрос: он дал тот же результат с меньшими затратами.
